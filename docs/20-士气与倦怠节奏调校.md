# 士气与倦怠节奏调校（2026-10-30）

用户反馈士气消耗快，并确认倦怠的问题是“员工很快变累，倦怠涨得快”。本次放缓日常消耗，保留长期工作、卷王、营销及进修的负担，不重置现有玩家状态。

## 调整

| 规则 | 调整前 | 调整后 |
| --- | ---: | ---: |
| 普通主任月度倦怠 | +8 | +5 |
| 普通机动队月度倦怠 | +5 | +3 |
| 卷王额外倦怠 | +5 | +3 |
| 营销活动额外倦怠 | +3 | +2 |
| 在职进修额外倦怠 | +3 | +2 |
| 士气向长期基准靠拢的月度比例 | 22% | 12% |
| 士气自然回落单月上限 | 无 | 3点 |
| 士气基准常数 | 28 | 34 |
| 口碑对士气基准的权重 | 0.22 | 0.24 |
| 平均倦怠对士气基准的扣减权重 | 0.30 | 0.22 |

管理能力和员工特质仍参与长期士气基准。轮休、专项培训、结业的直接恢复量保持原规则；欠薪、离职、剧情和经营决策造成的士气损失另算，不受3点自然回落上限保护。高倦怠对产出及离职的既有规则继续生效。

团队页直接展示每人的“本月工作倦怠预计”，包含岗位、特质、营销、进修及轮休效果，结业和临时事件另计。月报追加“士气自然调整”和“在编平均倦怠”，避免将日常消耗与剧情损失混淆。

新增参数集中在 `BALANCE.team`，进修负担沿用 `BALANCE.staff.studyFatigue`。两份HTML保持一致，存档版本与键不变；旧档直接使用新规则，不改写原有士气、倦怠、人员或资产。

## 验证

- 全套19组、0失败、0跳过，包括新增26项节奏定向回归和此前78项培养回归。日志：`tests/out/team-tempo/regression.log`。
- 定向覆盖普通岗位、高负荷叠加、轮休恢复、老油条、低士气回升、高士气回落上限、欠薪和事件损失、高倦怠边界、半年自然变化、读档不重置状态、实际按钮与月报显示。
- 固定两名普通员工，初始士气80、倦怠20，口碑保持60，不安排培养和轮休，不触发剧情：旧规则首月士气70.07，新规则77；半年后旧士气40.19，新士气62.04；主任倦怠旧68、新50，机动队旧50、新38。这只是隔离日常机制的工况对照，不代表实际玩家六个月必然得到同样数值。原始数据：`tests/out/team-tempo/six-month-comparison.json`。
- 最终1200局既有随机策略校准：收紧期不良率较宽松期高69%，通过40%门槛；完赛局中位存款26.35亿，相对历史基线26.81亿偏差−1.7%，通过±10%门槛。该策略的完赛率41.3%，不能当作真实玩家完赛率，也没有校准新增培养投资策略。
- Codex应用内浏览器通过本地HTTP验证员工卡片预计值与实际月报；390px、320px及1280px布局无横向溢出，浏览器警告/错误日志为空。使用内存隔离存档，没有读取或修改正常玩家存档；未进行真机触摸验收。
