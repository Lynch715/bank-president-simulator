# 《模拟银行行长》施工规范 v1.0(给 Opus5)

> 本文档是硬约束。与《01-设计建议.md》冲突时,以本文档为准;拿不准的设计问题,回问设计,不要自行发挥。

## 0. 总纪律

1. **单文件**:所有改动只发生在 `index.html`。不拆文件、不引任何 CDN/框架/字体。canvas 用原生 API。
2. **改完同步**:`模拟银行.html` 是 index.html 的副本,收工时 `cp index.html 模拟银行.html`。
3. **不许重写**:这是增量施工,禁止重构无关代码、禁止改写现有文案、禁止"顺手优化"。现有函数签名不动,新逻辑以新函数挂入。
4. **分期交付**:严格按 P0 → P1 → P2 顺序,每期结束跑完验收清单再进下期。P0 完成即是一个可发布版本。
5. 每期开工前备份:`cp index.html index.P0前备份.html`(git 不可用时的保底)。

## 1. 代码组织约定

- 新增代码统一放在对应现有区块之后,区块头注释格式与现有一致:`/* ============ 图鉴与成就 ============ */`
- 命名沿用现有风格:短小驼峰(`arcFav`/`nplRate`),数据常量全大写(`TRAITS`/`LOAN_POOL`)。
- **所有新增数值进 `BALANCE` 常量对象**(新建,放在 `OUTLET_POOL` 之前),禁止魔数散在逻辑里:

```js
const BALANCE = {
  cycle: { loose:[1,10], tight:[11,22], loose2:[23,36], jitter:2,
           tightNplMul:1.5, looseDeriveMul:1.1 },
  nim:   { baseYield:2.0, hiCostAdd:0.8, hiCostMonths:6 },   // 万/亿
  dirt:  { auditBase:0.12, perPoint:0.06, guardFav:80 },
  legacy:{ ptsPerRank:[100,80,60,40,30,20,10,5] },           // 阅历点
};
```

- 事件新增一律走统一 schema(现有 EVENTS 结构),新字段只允许:`weight`(默认1)、`once`(布尔)、`minMonth`、`routes`(数组,复用现有路线过滤)。不要发明新事件框架。

## 2. 存档兼容(最高优先级红线)

- `ver: 5 → 6`。在 `load()` 里写 `migrate(s)`:v5 老档补齐新字段默认值(`dirt:0`、`talents:[]`、`cycle:null`、`depCost:0`、`flags.faction:null`、`track.keyEvents:[]` 等),**老档必须能继续玩到结局不报错**。
- 图鉴/成就/阅历点/天赋解锁存独立 key:`jbzh_meta`(JSON),与局内存档 `jbzh_save` 分离——删档重开不清图鉴。
- 所有 localStorage 读写包 try/catch(现有代码已是此风格,保持)。

## 3. 分期施工单

### P0(交付物:可发布版)

**P0-1 图鉴成就**
- 数据:`const ACHIEVEMENTS = [{id, nm, ic, desc, hidden, chk:s=>bool}]`,`chk` 在 `showEnd()` 和每月结算尾部各跑一次。
- 结局图鉴数据从 ROUTES/finalEnding 现有文案生成,不复制文案字符串,引用原对象。
- UI:标题页与结束页各加一个"📖 图鉴"按钮,复用现有 `showModal` 体系;未解锁项显示 `???` + 暗示句。
- toast:新增极简 `toast(msg)`,fixed 顶部,2.5s 自动消失,不阻塞。

**P0-2 行长传记长图**
- `log()` 加可选参数 `key`(布尔);对以下事项补 `key:true`:路线选定、每次开网点、军令状成/败、年考成/败、每个 NPC 弧完结、黑天鹅各幕(P1 后)、结局。
- `renderBiography()`:canvas 宽 750px,高度按内容伸缩(时间轴 8~12 条,超出按月份均匀抽稀)。内容:称号、玩家名、路线徽章、时间轴、五维雷达(存款/口碑/士气/干净度=100-风险、人脉=NPC均好感)、一句总评(按结局档位写 8 句备选)、右下角贴现有 `bank-president-promo-qr.png`(以 Image 载入,失败则跳过不报错)。
- 下载:`canvas.toBlob → a[download="行长传记.png"]`。微信内置浏览器不支持下载时,提示"长按图片保存"并将 canvas 转 img 展示。

**P0-3 开局天赋**
- 终局时 `meta.exp += BALANCE.legacy.ptsPerRank[rank-1] + 路线目标达成?50:0`。
- `const TALENTS = [{id, nm, ic, desc, cost, apply:s=>{}}]`,10 个;`apply` 在 `newGame()` 里 `chooseRoute` 之后调用。
- 首周目(`meta.runs===0`)不显示天赋界面。天赋选择 UI 复用 `showModal`。

**P0-4 结算降噪 + 趋势图**
- `endMonth()` 组装 fns 时:若本月无 arc/chain/rival/event 且非季末/年末,月报弹窗按钮直接是"进入下月"(合并 nextMonth)。
- 弹窗限流:fns 中"剧情类"超过 3 个时,把随机事件(fireEvent 产物)延到 `S.deferredEv` 下月优先触发。军令状、年考、终局永不延。
- 趋势图:`S.track.depHistory`(每月 push,最多 36),月报顶部 canvas 迷你折线。

### P1(交付物:深度版)

**P1-1 宏观周期**:`S.cycle` 在 newGame 生成(节点±jitter 抖动);`settleCore` 读取阶段施加乘数;**提前2月**在月报 lines 头部插一条新闻(文案见 §5 示例)。收紧期 `pickEvent` 中检查类事件 weight×2(在现有按路线过滤后乘权重)。
**P1-2 净息差**:替换 `const income = Math.round(S.dep*2)` 为 `贷款月息合计 + S.dep*BALANCE.nim.baseYield − S.dep*S.depCostRate`;新增行动"高息揽储"(挂进 actManage 菜单,1精力)。**校准要求**:用 §4 基准脚本跑 200 局,三年存款中位数与现版偏差 ≤10%,破产率偏差 ≤3 个百分点;调 BALANCE 直到达标,把校准结果写进交付说明。
**P1-3 把柄**:盘点现有 EVENTS/arc 中灰色选项(判断标准:文案含贿/瞒/灰/造假/挪等,约15处),在其 fn 里加 `S.dirt += 1或2`(标准:可退赃的+1,刑事级+2,由施工者列表后交设计确认再写死)。年审事件掷骰:`p = auditBase + dirt*perPoint`;顾清越≥80 消耗 `used80` 挡一次。新失败结局 2 个 + 隐藏结局`干净的第一名`。UI:risk 栏 dirt≥3 时加 🗂 图标,title 提示"有些事,经不起翻"。
**P1-4 站队**:第 20~24 月随机一月强制 arc 事件(不占 pickArcBeat 名额,单独插入 fns);`flags.faction ∈ {lu, gu, null}`;各解锁 2 个专属事件(routes 字段外新增 `faction` 过滤字段,仅此一处扩展 schema);终局 `finalEnding` 按 faction 与最终胜方(月36随机+dirt影响)加一段文案。
**P1-5 黑天鹅**:`const BLACKSWANS = [...]` 3 套,每套 3 幕,复用 `S.chain` 机制(schedule);第 8~11、20~23、30~33 月各触发一套(不重复)。当月黑天鹅幕优先级高于随机事件。

## 4. 自测与模拟脚本

现有代码已导出 debug 函数(index.html 尾部 `genCandidates, pickEvent, fireEvent...`)。施工时补一个 console 可跑的模拟器:

```js
function simRun(policy="random"){ /* 新档→循环36月:随机花精力、事件随机选项、
  跳过所有 showModal(直接执行 opts[ri(n)].fn)→ 返回 {dep, rank, cash, ending} */ }
function simBatch(n=200){ /* 跑n局,输出中位数/破产率/结局分布 */ }
```

- 每期收工前跑 `simBatch(200)`,零 console 报错为硬门槛。
- 手工冒烟:新开局完整点 3 个月;读 v5 老档点 2 个月;窄屏 390px 过一遍新 UI。

## 5. 文案规范(重要,本作的命根子)

- **风格**:白描、短句、重庆味、不解释情绪。写"陆明远把茶杯放得很响",不写"陆明远很生气"。
- 数值反馈写进叙述结尾,格式沿用现有:`口碑+4` `存款-0.8亿`。
- 新闻预告示例(P1-1):`「同业群里在传:总行三季度要收信贷额度。真假不知,但老陈已经开始催收了。」`
- 禁用:感叹号连用、网络烂梗、翻译腔("哦我的天")、直白说教。
- 所有新增文案先集中列在代码的数据常量里(与现有 EVENTS 风格一致),便于设计通读校对。

## 6. UI/性能

- 复用现有 CSS 变量与 `showModal`/`report`/`log` 体系,新组件不新开配色。
- 列表渲染沿用 innerHTML 拼接批量写入,不逐节点 append(与现有一致)。
- canvas 只在结算/传记时绘制,不进每帧循环。
- 移动端:新增可点元素最小 40px 高;传记长图按 devicePixelRatio 绘制防糊。
