# 手机海报保存与分享兼容修复

## 确认的问题

旧实现 `ffc24fb` 在独立测试环境中可复现：`Canvas.toBlob` 缺失时，或 `URL.createObjectURL` 抛错时，保存按钮一直禁用，尽管 Canvas 仍能通过 `toDataURL` 输出正常 PNG。不支持文件分享时则隐藏分享入口，没有操作指引。图片预览加载失败时也没有恢复入口。

浏览器验收还发现：禁用临时图片地址后，点击 data URL 下载未产生下载事件。因此该分支改为直接打开原图保存页，不将它记录为成功下载。

## 修复后的操作

- 正常环境点击“保存海报图片”下载 PNG；点击“长按保存原图”打开单独的保存页，展示真正的高清 IMG 和返回结算按钮。原图页可继续下载或系统分享。
- 编码接口缺失、抛错、返回空值或超时，改用 `toDataURL` 生成 PNG。FileReader 不可用时也有备用路径。预览使用 PNG data URL，下载和系统分享分别使用预生成的 Blob/File，不依赖同一条临时地址。
- 临时地址无法创建或浏览器缺少下载属性时，主按钮显示“保存海报（长按）”，点击直接打开原图页；不显示无效下载按钮，不跳离结算页面。
- 支持图片文件分享时显示“系统分享”；不支持或能力检查失败时显示“分享方法”，说明先保存、再去朋友圈/小红书选择照片发布。
- 分享失败自动进入原图页；取消分享保留结算页，不自动下载或打开新窗口。结算页和原图页共用分享忙碌状态，防止重复调起。
- 预览加载失败时出现明确提示和重新生成按钮。返回、重试和分享不重新结算、不写存档/阅历/图鉴；重开清理原图、临时地址和回调状态。

分享文件在结局绘制时已经准备好，点击回调中直接调用系统分享，不在点击后等待生图或图片编码。这符合 [WebKit 对用户激活的说明](https://webkit.org/blog/13862/the-user-activation-api/)。

## 验收结果

- `bash tests/run-all.sh 400`：17 组通过，0 失败，0 跳过。原海报 34 项、新增手机操作兼容 39 项全部通过。
- `tests/17-mobile-poster-actions.js` 覆盖编码接口缺失/异常/空值/超时、临时地址缺失/异常、缺 FileReader/Blob/File、无系统分享、能力检查异常、下载抛错、分享拒绝/取消、预览错误、并发分享、返回以及异步重开。
- 最后回归暴露旧 `02-meta.js` 的随机断言：合法的“组织处理”结局可能不解锁任何成就。该测试现明确满足六十亿条件再核对对应成就，不再要求随机剧情一定给出成就；游戏规则未改动。
- 应用内浏览器实际导出正常环境的 PNG：1080×1440、2,121,504 字节；二维码经 Vision 解码为线上游戏地址。文件保存在 `tests/out/mobile-poster-download.png`。
- 应用内浏览器 320×568、禁用 MutationObserver、无编码接口与无临时地址时，仍生成 1080×1440 原图。原图页无横向溢出，保存/返回按钮高度大于 44px，滚动后返回可达。
- 390×844 验证分享拒绝后自动打开原图、分享取消后按钮恢复；模拟接口收到真实 `image/png` 文件。临时地址受限时点击保存直接打开原图，没有重复下载死路。
- 844×390 原图页可滚至返回按钮，按钮完整落在视口内；无横向溢出。
- 本轮使用隔离内存存档验收结局，未推进或重开线上玩家的存档。上述为浏览器尺寸和 API 能力模拟，未在实体手机上验证相册写入或微信/小红书客户端发布。
