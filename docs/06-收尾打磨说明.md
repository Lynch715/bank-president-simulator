## 一、补掉的五个缺口

都是我在 P0/P1/P2 三份交付说明里自己写进「已知问题」的那几条。

**1. 传记长图补上 P1/P2 的信息**
标题下面加了一行**履历标签**(胶囊样式,自动居中):挑战模式 → 站队(⚑业务派 / ⚖合规派 / 🌫骑墙)→ 把柄程度(🕯手上没东西 / 🗂沾过一点 / 🗂手上有东西 / 🗂一身是把柄)→ 🦢黑天鹅×N → ✍️军令状×N。页脚补上本局种子,别人拿着就能开同一局。传记高度对应加了 32px。

**2. 雷达「干净」维度改成综合 dirt**
原来只读风险峰值,一个满手把柄但风险压得低的行长,雷达上照样「干净」——这跟 P1 的立意是拧着的。现在:`干净 = 100 − 风险峰值×0.7 − 把柄×6`。把柄 4 就直接扣 24 分,雷达上看得出来。

**3. 收紧期存款流失率挪进 `BALANCE`**
`BALANCE.cycle.tightDrain: 0.004` 和 `drainCap: 80`,不再硬编码在 `settleCore` 里。这是 P1 遗留的唯一一个魔数,现在 BALANCE 是完整的了。

**4. 平静月的月报也塞一条同业群消息**
原来同业群只在季考出现,一局 12 次。现在中期留白那种「什么都没发生」的月份,月报里会多一行同业群的动静——那个月本来就是最空的一屏,正好用它填。

**5. 雷达标签溢出**
出图核对时发现最右侧那个轴的标签会顶出画布边缘(750px 宽的图,标签画到 772)。已经改成按实际文字宽度夹住,并把雷达整体左移 18px、半径收 4px。

## 二、顺手动的一个数

`BALANCE.cycle.tightNplMul` **1.5 → 1.65**。

原因不是手感,是验收线不稳:规范要求「收紧期不良发生率高于宽松期 ≥40%」,1.5 跑出来的实测值在 32%~50% 之间摆(名义 1.5 倍会被跨周期存续的贷款稀释),200~300 局的样本量下会偶尔掉到线下。1.65 之后稳定在 55%~58%,有余量了。完赛局中位存款只从 25.5 变到 25.4,基本没动。

## 三、新增 `tests/` 目录

以前的测试脚本都散在我的临时目录里,这次固化进项目。**游戏本体依然是单文件零依赖,发布只需要 `index.html` 加那几张图**;`tests/` 只服务于回归。

```
tests/
  run-all.sh      一键跑全套
  lib.js          公共加载器(把 <script> 抠出来在 Node 里跑)
  01-headless.js  无头 200 局,硬门槛零报错
  02-meta.js      P0:老档迁移 / 图鉴成就 / 10个天赋 / 传记绘制
  03-p1.js        P1:周期 / 把柄 / 站队 / 黑天鹅 / 净息差
  04-p2.js        P2:种子复现 / 三个挑战 / 对手剧本 / 同业群
  05-ui.js        jsdom 真点按钮走完整流程(需 jsdom)
  06-balance.js   数值校准 + 按周期统计不良,自动跟基线版对比
  07-clicks.js    点击数统计,跟原版比(需 jsdom)
  08-bio.js       传记出真图到 tests/out/,肉眼核版式(需 canvas)
  README.md       每组测什么、几个坑
  package.json    两个测试依赖,装不上会自动跳过
```

`bash run-all.sh` 会先做语法自检、顺便检查 `模拟银行.html` 跟 `index.html` 是否同步(这个我自己忘过一次,现在跑测试会红给你看)。需要依赖的三组装不上就跳过,不阻塞。

`lib.js` 里带一个 `shim()`,给 P0 之前的老版本补无头守卫——这样新旧两版能用同一套策略跑,`06-balance.js` 的对比才成立。

## 五、仍然没做的

- **真机(浏览器)验证没做**。所有 UI 测试跑在 jsdom 上,canvas 是哑实现。真实浏览器下的观感、窄屏 390px 的实际排版、微信内置浏览器的下载行为,都还没有人眼看过。发布前建议实机过一遍。
- **二维码在 `file://` 下会污染 canvas**,导致传记的下载按钮失效(代码已回落到「长按图片保存」)。正式发布走 http(s) 就没这个问题。
- **三份交付说明里累计 12 个「需要设计确认」的问题仍然挂着**(巡视组要不要更冷酷、速通要不要等难度、挑战要不要专属结局、每局自动种子要不要保留等等)。这些是设计决策,我按自己的判断做了默认实现,都写了怎么改回去。
